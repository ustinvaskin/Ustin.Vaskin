RESEARCH / LANGUAGE DESIGN / AI

TundraTrace.

What if a model could see how a program reached its mistake?

I built a small language, interpreter, and benchmark to study when runtime evidence helps language models repair code.

Explore the results ↓
{t}

THE QUESTION

Follow
the evidence.

An error message tells you something went wrong. It might not show where the responsible value came from or which path the program took to get there.

I wanted to compare repairs with and without that extra context. TundraTrace captures compact runtime evidence, such as value provenance, and gives it to a model alongside the failing program.

Tundra is a small interpreted language that keeps the experiment controlled. It lets me study the effect of evidence on repair, with a repeatable set of tasks.

A SMALL EXAMPLE

Where did
the value come from?

A failure can point to an addition. A trace can also follow the value back to its source.

EXPERIMENTAL RESULTS

Helpful,
sometimes.

The frozen study compares three models across 36 tasks, with three trials under each condition. The aggregate result is promising, but evidence did not help every model or task.

ERROR OR FAILURE ONLY59.9%

194 of 324 normalized repairs succeeded.

WITH RUNTIME EVIDENCE70.4%

228 of 324 normalized repairs succeeded.

This is a controlled benchmark in a small custom language. The study found an overall advantage, but the cleanest low-leakage subset did not show a stable benefit. These results do not establish the same effect in mainstream languages or production systems.
