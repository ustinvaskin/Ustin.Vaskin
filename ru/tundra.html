ЯЗЫКИ ПРОГРАММИРОВАНИЯ / ИССЛЕДОВАНИЕ ИИ

TundraTrace.

Легче ли ИИ исправить ошибку, если он видит, что было до сбоя?

Я создал небольшой язык программирования, инструмент для запуска кода и набор задач. С их помощью я проверил, когда данные о запуске помогают языковым моделям исправлять ошибки.

К результатам
{t}

ИДЕЯ

По следам
ошибки.

Сообщение об ошибке помогает найти место сбоя. Иногда приходится разбираться дальше: какой путь прошла программа и откуда взялось значение, из-за которого всё остановилось?

TundraTrace ведёт краткий журнал запуска — трассировку. По нему можно узнать, откуда взялось значение. В эксперименте я давал модели один и тот же код с ошибкой и проверял, меняется ли результат, если добавить журнал.

Для эксперимента я разработал небольшой язык Tundra. На нём удобно составлять задачи и повторять их в одинаковых условиях.

ПРИМЕР

Откуда взялось
значение?

Программа пытается прибавить 5 к цене. Сообщение об ошибке говорит, что складывать число с текстом нельзя. Журнал показывает, что цена записана как «10» — в виде текста.

Попробовать самому

ПРОГРАММА

val raw = { price: "10" };
val total = raw.price + 5;
print(total);

ДАННЫЕ О ЗАПУСКЕ

Cannot add String and Number
raw.price was string "10"

Как всё устроено.

Код и задачи

РЕЗУЛЬТАТЫ ЭКСПЕРИМЕНТА

В среднем
помогает.

Я проверил три модели на 36 задачах. Каждая модель решала каждую задачу по три раза с данными о запуске и по три раза без них. Перед проверкой я убирал из ответов пояснения и разметку, чтобы оценить сам код.

БЕЗ ДАННЫХ О ЗАПУСКЕ59,9%

194 успешных исправления из 324 попыток.

С ДАННЫМИ О ЗАПУСКЕ70,4%

228 успешных исправлений из 324 попыток.

Журнал помогал по-разному в зависимости от модели и задачи. Там, где данные почти не подсказывали, что исправить, устойчивого улучшения не было. Повторится ли этот эффект на других языках и в реальных проектах, ещё предстоит проверить.
